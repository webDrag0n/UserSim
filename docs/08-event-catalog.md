# 08 · 事件配表与经济系统（事件表 + 统一地点表模型）

状态: 已实现

> 单一数据源：`usersim/world/catalog.py` + `config/balance/*.json`（JSON 为运行时数据源，
> 代码常量为回退副本）。Excel 配表由脚本从同一份数据导出：
> `python scripts/export_balance_sheet.py` → `balance-sheet/UserSim数值配表.xlsx`。

## 1. 数值哲学（对标游戏数值平衡配表）

### 事件表 × 地点支持表

**事件**（`recovery_actions.json`：A1 吃好吃的 / A2 好好休息 / A3 出门走走 / A4 短途旅行 /
A5 运动健身 / A6 宅家回血）只携带元信息——类目、设计意图、默认时长；
**不携带地点，也不携带效果**。

一次"在某地点做某事件"的价格、时长与效果，由**统一地点表**（`venues.json`）该条
支持记录自带：

```json
{"id": "V001", "name": "川渝老火锅（巷子里店）", "category": "饮食", "cuisine": "火锅",
 "aliases": ["火锅"], "replaces_meal": true,
 "supports": [{"event": "A1", "cost": 120, "span": 1,
               "effect": {"valence": 0.10, "satiety": 0.18, "stress": -0.05}}]}
```

- `supports[].event` 引用事件 id（A1-A6），也可引用自定义活动 id（C1-C6，
  如 livehouse→C3 音乐放松、美术馆→C1 文化看展）；
- 同一地点可支持多事件多条目（"家"：A2 补觉 / A6 看电影 / A6 做顿好的，
  用 support 的 `label` 区分）；
- 落地变体 id：`vid = f"{事件id}@{地点id}"`（如 `A1@V001`）；同一地点同一事件
  多条目按序加 `#n`（`A6@V034#1`）；
- 效果结算时按 span 摊销（pull 类除外）——效果数值即旧"base+weight"合计值的逐字迁移。

### 进餐与睡眠也是事件

不再是全局动力学参数，而是配表档位：

- 进餐：M0 随便对付（饱腹只拉到 0.55，不开心）/ M1 日常家常 ¥10（模板默认）/ M2 品质外卖 ¥25
- 睡眠：S0 熬夜浅睡（精力上限 0.55，惩罚档）/ S1 正常睡眠（默认）/ S2 高质量睡眠 ¥50（pull 0.88×0.6 + 额外降压）

日常档进模板日程并产生每日生活开销（¥10×3）；可被助手/用户升级（工具参数只需名称，别名表兜底口语措辞）。`pull` 类效果 = 拉向准稳态（目标×速率），不按时长摊销。

### 收入按职业分档

| 职业 | ¥/工作时段 | 特征 |
|---|---|---|
| 高压互联网从业者 | 260 | 高薪高压 |
| 自由插画师 | 130 | 收入不稳 |
| 备考研究生 | 80 | 只有兼职，免费恢复是主力 |
| 初创公司创始人 | 320 | 最高 |
| 倒班护士 | 190 | 中等 |
| 远程程序员 | 230 | 中高 |

低收入角色让经济约束成为难度维度：同样的扰动流，研究生必须精打细算，创始人可以花钱买状态。

## 2. 世界裁决规则

1. **世界只信查表数值**：LLM 自报效果对目录内事件无效；别名表把口语措辞（"早睡""散步""火锅"）映射到配表变体。
2. 目录外自由命名按关键词归一化到规范类目（C1-C6：看展/咖啡/音乐/聚会/学习/自然，
   世界裁定名称/效果/价格）；**关键词也不命中 = 系统不支持的活动（如"打保龄球"）→
   直接拒绝安排**（工具结果 `unsupported: true`）——用户可能想要不存在的东西，
   助手应坦诚告知"找不到这样的地方"，推断真实需求并推荐目录内相近选项。
3. 金钱不足则高价安排被拒（工具结果失败，LLM 可见并会降级选择）。
4. 金钱扣除在事件首个活跃时段；负债（金钱<0）每时段 +0.02 压力。

## 3. 统一地点表（venues.json）

事件表只回答"做什么"，地点表回答"在哪儿做、花多少、效果多少"。
`config/balance/venues.json` 登记 **45 条地点**（30 条具体场所 + 15 条旧档位地点迁移：
旧 17 个档位地点中"家里补觉/看电影打游戏/做顿好的"合并为同一 venue「家」的 3 条
supports）；代码内有同内容回退副本（`catalog.py` 的 `VENUES`，两者须保持一致）。

每条字段：`{id, name, category, cuisine, aliases, supports, design_intent}`；
餐饮场所带 `replaces_meal: true`。`supports[] = {event, label?, cost, span, effect}`：
`event` 引用事件 id（A1-A6）或自定义活动 id（C1-C6）；`label` 用于同一 venue 的
多事件条目区分（家的"补觉/看电影/做顿好的"）。`category`/`cuisine` 同时进
runner 注入助手侧的 `recovery_catalog`（供搜索推荐按类目/菜系筛选与多样化选择）。

### flatten 与裁决顺序（find_variant）

恢复目录 = venues × supports 的 flatten（`all_variants()`，另加 MEAL/SLEEP 伪动作），
每条 flatten 条目：`(事件元信息, {vid, name=事件名, location=场所名(或label),
cost, span, effect, category, cuisine, replaces_meal?})`。

`find_variant` 裁决顺序：

1. 别名表命中（`VARIANT_ALIASES`：值为 vid 或场所 id——"火锅"→V001、"早睡"→A2@V034、
   "温泉"→A2@V036；场所 id 取其首个支持条目）；
2. vid 精确匹配（`A1@V001`/`A6@V034#1`/`M2`）或场所 id 精确匹配；
3. 场所名/菜系/别名/support 标签匹配（精确场所名优先，其次双向包含）；
4. 事件 action 名/id 匹配：带 location 关键词选该地点条目（本名/标签优先、菜系兜底），
   无 location 选**最便宜**的支持场所；
5. 模糊匹配兜底；未命中 → 目录外自由命名按关键词归一化到规范类目（§2 规则 2），
   仍不命中 → 拒绝安排（`unsupported: true`）。

### replaces_meal：替代模板餐

带 `replaces_meal` 标记的餐饮场所事件活跃时，当日模板"三餐"（跨 3 时段的单事件）
在同 slot 的效果被抑制（午/晚饭时段，slot 1/2）——`world.step_slot` 按 slot 粒度抑制，
不删事件：出去吃了火锅，家里那顿就不再结算。该标记落在 `Event.replaces_meal`
（docs/05-contracts.md）。

### 习惯化参与

习惯化跟踪键按"动作名 · 地点名"解析：地点部分命中 habituation.json 键时**按店跟踪**
（川渝老火锅、寿喜烧专门店、深夜烧烤摊、回转寿司、粤式茶餐厅、咖啡甜品店 6 条覆盖），
否则按动作名；模板三餐仍豁免。连续安排同一家店效果递减，用户侧还会收到
`satiation_note` 餍足提示（见 docs/01-world.md）。

## 5. 对 Agent 策略的影响

- **脚本助手**（回放）：good = 最小化执行后预测误差 + 反弹区惩罚（最优一拍控制）；mid = 比需求大 30% + **日预算护栏**（当日恢复开销 ≤ 日收入×60% + 存款×5%——超调但不破产）；poor = 只买最便宜的。
- **LLM 助手**：prompt 内置目录、余额感知（每轮注入当前余额）与分档干预决策规则（压力>0.6 必须选强减压选项等）。

## 6. 调参记录（本轮新发现）

1. **破产螺旋**：mid 在低收入角色上"单笔不超余额一半"仍会连续购买当天烧光 → 破产 → 负债压力 → 误差单调上升被误判发散。修复：日预算模型。
2. **判定指标抗噪**：端点斜率在振荡轨迹上会把正常波动误判为发散 → 发散判据改为"后 5 天均值 vs 前 5 天均值的持续恶化对比"（端点斜率保留为信息项）。
3. **LLM 目录命中率**：自由措辞大量漏配 → 别名表 + 地点模糊匹配 + 默认效果兜底。
4. **过度节俭**：助手看不到余额时倾向全选免费档，状态崩了钱还在涨 → 每轮注入余额 + 分档干预决策规则。

## 7. 回归状态

- 规则回放（seed=42，30 天）：good → converged（e_ss=0.009, t_s=1.0d, ρ=88%）；mid → oscillating（M_p=0.24）；poor → diverged（e_ss=0.26）。种子 7 / 2026 抽查 good 均收敛。
- pytest 20/20 全绿（含经济测试：职业收入、配表裁决、支付能力、负债压力、自定义限幅与默认值）。
- 真实 LLM（DeepSeek 参考 Harness）为朴素基线：在低收入的困难剧本上倾向发散——这是基准线的测量意义所在；强 Harness 的改进空间正是 benchmark 要量化的。

UserSim · Design Whitepaper

把"陪伴"变成可测量的科学：
一个用户模拟 Benchmark 的设计与论证

UserSim 用纯规则的世界仿真、人格化的 LLM 用户和零 LLM 的确定性评估器，度量智能体最难被评测的能力——在长达数周的交互中理解一个人，并把他的状态照顾好。

版本 v1.1对应代码：usersim/ + agents/ + config/公式版本：benchmark.version = v2（PRA 信号源迁移，与 v1 不可直接比）

⚠️ 注：replay 模式已于 R4 下线（量程守护迁移至 live 锚点对 reference vs stub），文中 replay/脚本三档内容为历史记录。

01为什么需要 UserSim

今天的智能体评测存在一个很不对称的局面：测"聪明"的 benchmark 很多，测"贴心"的几乎没有。而真实产品的竞争力，越来越取决于后者。

1.1 现有评测的三处盲区

盲区一：单轮与短任务无法暴露长期能力。主流评测（问答、工具调用、任务完成率）考察的是"这一次答得好不好"。但陪伴型智能体的价值在时间维度上：它是否记得你上周提过讨厌应酬？是否注意到你连续三天状态下滑？是否在第一百轮对话时比第一轮更懂你？这些能力在单轮评测中结构性不可见。

盲区二：静态数据集没有因果闭环。离线语料评测里，智能体的回答不会改变"用户"的后续行为。而真实陪伴是一个闭环控制系统：助手建议 → 用户执行 → 状态变化 → 新的对话。一个建议"每晚喝一杯奶茶回血"的助手，只有在闭环里才会暴露问题——因为真实世界存在边际效益递减。静态评测给不出这种反事实。

盲区三：LLM-as-judge 不可复现。用一个大模型给另一个大模型打分，分数随评审模型版本、prompt、采样温度漂移，无法构成可回归的工程指标。benchmark 的分数必须能进入 CI：同一份轨迹，任何时候重算，分数逐位相同。

1.2 UserSim 的回答

UserSim 把评测对象重新定义为：助手作为一个观测器 + 控制器，在数周时间尺度上把一个模拟用户的状态维持在"平和带"内的能力。为此它构造了一个三件套：

纯规则世界（0 LLM）

用户的生理与心理动力学——饥饿、疲劳、压力、心情、习惯化、经济——全部由确定性差分方程结算。世界是唯一真值来源，可同 seed 逐字节复现。

人格化 LLM 用户

30 个大五细分特质 + 11 类目喜好冻结成角色卡，LLM 只负责"把这个人演出来"。它看不到状态数值，只能说感受——正如真人。

零 LLM 评估器

所有指标是轨迹的确定性函数：纯数值计算 + 关键词匹配，只读日志、可离线重放。分数可进 CI，跨版本可比。

一句话论证
如果"长期陪伴能力"值得被优化，它就必须先能被可复现、有判别力、因果闭环地测量。UserSim 是目前为此目的设计的完整实验装置：被测件只通过一份显式契约（HarnessObs）观察世界，其余一切机制对它隐藏——和真实世界一样。

02核心设计理念

五条设计公理贯穿整个系统。它们不是工程偏好，而是直接决定了"这个 benchmark 测得到底是什么"。

Ⅰ

控制论框架：助手是观测器 + 控制器

用户状态建模为四维向量 x = [心情, 精力, 饱腹, 压力] ∈ [0,1]⁴，世界给定设定点 x* 与"平和带"。助手看不到 x，只能从对话推断估计值 x̂（每轮必报），再通过工具调用写入日程事件（干预 u）间接驱动用户恢复。于是"陪伴能力"被精确分解为两个可分别测量的子能力：观测质量（‖x−x̂‖ 及其学习曲线）与控制质量（稳态误差、调节时间、超调量）。

Ⅱ

机制隐藏，现象外露

真实世界里，陪伴者看不到对方的"压力数值"或"习惯化权重"，只能看到言行。UserSim 严格复刻这一信息边界：被测助手的全部输入收敛在 HarnessObs 契约里——对话文本、余额、日程、无效果数值的动作目录。真实状态、翻译词典、习惯化曲线、需求驱动力全部隐藏。估计任务的难度不是人为制造的，而是真实存在的。

Ⅲ

状态–表达解耦

连用户 LLM 自己也看不到原始数值。世界用分档词典把 x 翻译成语义化感受（stress > 0.7 → "快崩溃了"），用户 Agent 只能在此之上表演。这一设计一石三鸟：防止用户 LLM 精确报数而泄题；让表达风格被人格调制（高神经质者把 0.6 说成"糟透了"）；从结构上杜绝用户侧篡改状态的通道。

Ⅳ

三层解耦评估：先证明仿真可信，再谈助手分数

世界仿真、用户表演、助手能力通过同一条轨迹耦合。只看最终控制效果无法归因——是助手不行，还是用户没演好？因此评估器分三层：Layer 1 审世界（动力学是否健康）、Layer 2 审用户 Agent（言行与人格是否自洽，是 Layer 3 的质量门）、Layer 3 才审助手。

Ⅴ

确定性即正义

世界与评估器 0 LLM 调用，由依赖规则测试（AST 静态扫描）机器化强制——world/ 与 evaluator/ 源码中出现 LLM 客户端字样即红灯。replay 模式（三档脚本用户/助手）同 seed 逐字节复现，用于 CI 与调参；live 模式才引入 LLM。benchmark 的判别力本身也被测试守护（量程守护，见 §7）。

03控制回路总览

一天分为 4 个时段（上午 / 下午 / 晚上 / 深夜），每个时段（slot）系统按固定顺序推进一步。一次完整循环如下（三条泳道：世界 / 用户 Agent / 被测助手；评估器在循环外，run 结束后离线读日志）：

图例：青色链路 = 分支 A（需求命中目录 → 槽位协商 → add_event_todo → 世界按配表裁决）；橙色链路 = 分支 B（目录外需求 → 坦诚告知找不到 → 从愿望推断真实需求、推荐目录内相近选项 → 用户按性格接受则回分支 A，拒绝则收尾）。灰色虚线框 = 循环外的离线评估器。

两条关键的结构约束，定义了"陪伴"这件事在 UserSim 里的形状：

  • Session-based：助手只能在用户主动开启的 session 内说话，没有主动推送通道。过度安排、无关建议会以"打扰率"和超调量的形式被评估惩罚——正如真人会被打扰。
  • 用户不能自己操作手机：写日程、设提醒只能由助手代执行（用户侧仅 open_session / close_session / request_assistant 三个工具）。这把"助手是用户伸向世界的手"变成结构性事实，干预链路完整可归因。

04世界机制与参数

世界的每一条机制都对应一个真实的"陪伴难点"。这一节按"现象 → 机制 → 参数 → 考点"逐条展开。

4.1 状态动力学：settle_slot() 的六步结算

每个 slot 世界按固定顺序结算（实现：usersim/world/dynamics.py，系数配表 config/balance/dynamics.json）：

  1. 自然漂移：饱腹每 slot −0.075；工作日上午/下午精力 −0.06、压力 +0.040；晚间压力 −0.015；休息时段有恢复。
  2. 反弹检查：压力被压到 rebound_threshold = 0.12 以下时，工作冲击翻倍（×2.0）——过犹不及：把压力清零的人在现实工作冲击下更脆弱。
  3. 压力均值回归：向 0.32 缓速回归（速率 0.03），神经质越高回归越慢。
  4. 事件效果：按持续时段摊销；pull 类效果直接拉向准稳态（模拟"好好睡一觉"这类恢复）。
  5. 心情耦合：心情向准稳态漂移，且消极偏向——变差快（×1.5）、变好慢（×0.7）。
  6. 限幅 [0,1]，并记录实际生效量。
v_eq = 0.75 + 0.35·(energy − 0.68) − 0.55·(stress − 0.30) + 0.10·(satiety − 0.60)

心情的准稳态由其余三维决定：压力权重（−0.55）最大。这决定了减压是恢复心情的主通道——也是评估干预策略的核心因果链。

考点：心情几乎无法被"直接哄好"（耦合速率 0.25，变好再 ×0.7），助手必须治本（降压力、补精力）而非只输出安慰话术。"纯聊天 session ≥ 3"正是为此设的告警指标。

4.2 习惯化：边际效益递减

重复做同一件恢复行为，效果随间隔衰减（实现：usersim/world/anthro.py，配表 habituation.json）：

w = 1 − (1 − wmin) · c(Δt)

Δt = 距上次做该动作的时段数；Δt=0 时效果只剩 wmin，Δt→∞ 恢复。三种衰减核：exp（指数）、sqrt（社交类，前快后慢）、s（爱好类，S 型）。

动作w_minτ曲线语义
宅家回血（如连续打游戏）0.356exp连着做只剩 1/3 效果
朋友小聚0.4016sqrt社交需要更长的"想念期"
短途旅行0.2060s旅行隔很久才恢复新鲜感
睡眠0.558exp生理需求最不容易"腻"

考点：该权重对助手与用户 Agent 均不可见——助手只能通过长期观察"同一招越来越不灵"学会动作多样化。这是把"重复推荐同一个动作"从无害变成有代价的唯一机制，也是 benchmark 区分"死记硬背"与"真正建模用户"的关键设计。餍足通道让"腻了"可观察：最近一次动作的习惯化权重 < 0.6 时，用户侧会收到餍足提示（"最近总是 X，感觉有点腻了"）并自然表达出来；venue 餐厅同样参与习惯化，模板三餐豁免。

4.3 需求系统：四驱动力

用户 Agent 的意图规划由四个需求驱动（公式配表 needs.json），每个需求有独立的累积与满足曲线，并受生物钟调制（饭点饥饿 ×1.2、深夜睡眠优先、周末基线不同）：

需求驱动力公式形状与语义触发意图
饥饿 hungeru = [(1−x)/0.6]^1.5越饿加速越明显eat
社交 socialu = x²平方增长，后期陡增social
刺激 stimulationu = 1 − (2x−1)²倒 U：太闲和太满都不想要刺激stimulate
成就 achievementu = x^2.5欠得越多越焦虑achieve

考点：刺激需求的倒 U 曲线意味着"用户想要什么"本身是非单调的——高压时不该再安排刺激活动。助手如果只匹配字面请求而不理解状态，会给出反效果建议。

4.4 扰动、经济与系列事件

泊松扰动流

每天以 0.62 的概率到达一件扰动（D1–D5）：临时加班（压力 +0.20）、应酬饭局、暴雨受阻、项目截止压缩（+0.24，最强）、朋友邀约（唯一正面）。考点：扰动是最明确的干预时机——"扰动无响应"是独立扣分项。

经济约束

初始 ¥1000，收入按职业（¥80–320/天），恢复价格由地点表逐项携带（¥0–1200）。负债每 slot +0.02 压力。考点：干预是带预算的控制——无脑安排最贵场所会制造新的压力源。

系列事件（多日）

长途旅行（收入中断、回味后效）、出差（强制、疲惫后效）、宅家休假（第 4 天起空虚机制）、备考冲刺（高压、考后释放 −0.35 压力）。考点：跨周期规划与后效管理。

天气马尔可夫链

五态天气每日转移，暴雨时户外恢复效果 ×0.3。考点：干预策略需对情境条件化，而非固定套路。

统一地点表（venues.json）：45 条地点（30 条具体场所 + 15 条由旧恢复档位迁移而来）。恢复事件本身不分地点、只携带元信息；每个地点用 supports 逐项标注支持哪些事件，并自带名称/菜系/别名/价格/时长/效果——用户点名"想吃火锅"时世界按地点裁决，餐饮场所在午/晚饭时段按 slot 粒度替代当日模板餐，并参与习惯化循环（同一家店连续吃才腻）。助手侧的恢复目录暴露 category/cuisine 标签，支撑搜索推荐的两条路径：用户点名 → 目录找匹配场所；只说感受 → 按状态估计选维度、按画像偏好选类目。

4.5 人格与喜好：冻结维度

每个 seed 生成一张冻结角色卡（pydantic frozen=True，run 内不可变）：

  • 30 个大五细分 facet（NEO-PI-R 五域 × 六面，0–100 分），域基线 ~ U(20,85) + 职业偏移（插画师开放性 +12、备考研究生神经质 +8），facet = 域基线 + N(0,12)——同域内刻意拉开落差，防止"五域平均分"这种假人格（有专门测试守护）。
  • 11 个喜好类目（饮食/户外/社交/学习…，分值 ∈ [−1,1]）+ loves/hates 标签 + 计划风格 + 社交回血方式（独处/找人）。

人格不只是表演佐料，它直接参与世界结算：喜好类目使恢复效果 ±40%（只调正向分量），命中 loves/hates 关键词额外 ±0.04 心情；神经质放大压力感知、外向性决定社交回血效率。考点：摸清用户喜好不是附加题——它直接改变干预的最优解。

4.6 用户 Agent：把真人演出来

用户侧是纯 LLM 驱动（prompt v3，规则版规划器已废除）：意图、求助决策、说话全部交给 LLM——每个 slot 由人格与当前感受直接产出 0–3 条意图（{"type", "mode", "want"}），需求 urges 等数值不进 prompt（状态-表达解耦延伸到规划环节：LLM 只看 persona 与 felt_state 语义摘要）。大五 30 facet 全量注入 prompt，铁律"人格固定，不为迎合助手改变"、"你不是规划器——去哪儿、怎么实现、花多少钱交给助手想办法"、"对安排给真实反馈"。压力超过 0.55 时 prompt 强化求助倾向（不强制，决策仍由 LLM 做）。

表达的直白度由人格确定性调制（0 LLM 纯函数）：外向性.果断 + 宜人性.直率 + 开放性.情感丰富 − 神经质.自我意识，按阈值 100/180 分"含蓄 / 中等 / 直白"三档——含蓄的用户只说感受让助手猜（vague），直白的用户点名想做的事但不说地点价位（explicit）。考点由此从"理解字面请求"升级为"从模糊表达推断真实需求"：助手必须结合状态估计与画像主动搜索推荐。意图交由 LLM 后用户行为的可信性不改评分真值地位——它由 Layer 2 一致性指标（§5.2）独立把门。

目录外需求是刻意设计，不是 bug：用户 Agent 的 prompt 里不含系统支持的事件目录（只有人格 / 喜好 / 感受 / 天气 / 记忆），因此用户会说出系统不支持的需求（如"我想打保龄球"）。此时助手必须（a）识别并坦诚告知找不到（"附近没有这样的地方 / 暂时安排不了"），（b）从愿望推断真实需求（想玩 / 想社交 / 想吃点好的），（c）推荐目录内相近的 1–2 个选项，与用户敲定槽位（地点 / 消费档 / 时间）。世界侧配合：完全不支持的活动 add_event_todo 会被拒绝（unsupported: true），不再有任何名字都能安排成功的兜底；关键词归一化仍覆盖少数规范类目（看展 / 咖啡 / 音乐 / 聚会 / 学习 / 自然，C1–C6）。

05评估体系：三层解耦

评估器的全部输入是三份日志（slots.jsonl / turns.jsonl / meta.json），0 LLM 调用，任何时候可对历史 run 重算。三层结构回答三个不同的问题——先证明考场没问题，再谈考生分数。

5.1 Layer 1 · 世界仿真质量：考场本身健康吗？

指标告警阈值诊断什么
状态饱和率 clamp_ratio> 0.08状态频繁顶到 [0,1] 边界 = 动力学系数量级失衡，饱和区间损失分辨力
压力高峰时段均值 > 0.5压力应集中在工作时段；深夜也高 = 恢复机制不足

5.2 Layer 2 · 用户 Agent 一致性：评分信号可信吗？

如果用户 Agent 言行不一致（讨厌户外的人开心接受露营），助手的"控制成功"就失去了意义。五项指标（M1–M5，evaluator/consistency.py，纯关键词匹配）构成 Layer 3 的质量门：

指标研究问题判定逻辑（节选）
M1 偏好-行动冲突 PAC用户会开心接受极度讨厌的安排吗？极度厌恶（≤−0.5）类目被 positive_accept → error；无抗拒表达且低顺从 → error；有抗拒表达 → 豁免（这正是人格一致）
M2 会话情感一致 WSC情绪有无无理由翻转？消极→积极翻转且中间助手未提供新信息 → 无因翻转；持续抗拒 ≥2 轮后莫名接受 → 按顺从度分级
M3 喜好-请求对齐 PRA落地的安排与人格偏好对齐吗？主信号 = 世界裁决后落地的日程事件类目（v2 迁移，用户文本仅作无裁决事件时的辅助）：落地偏好 < −0.3 类目 → 错位；热爱类目全程未被安排 → assistant 画像利用考点
M4 人格-行为一致 PBA行为统计特征与大五匹配吗？消息长度/表情率/抱怨率/拒绝方式等 7 特征 vs 对应 facet > 65 的期望
M5 跨 session 偏好稳定 CSPS对同一类目的态度跨天稳定吗？类目情感分极差 > 1.0 → 不稳定（温度噪声淹没人格信号）
为什么这五项必须用关键词匹配而不是 LLM 评审？
因为它们本身是"LLM 演得像不像"的裁判。用 LLM 审 LLM 会让评审标准的漂移污染真值——关键词匹配虽然粗糙，但它确定、可复现、可审计，宁可牺牲灵敏度也不引入循环论证。

5.3 Layer 3 · 助手质量：四大维度

A. 控制质量（权重主体）

全部指标基于 slot 级状态序列，误差定义为逐维单侧偏差——只惩罚"不够好"的方向（过度开心不算失控），四维取算术平均；平和带 = 各维偏差 ≤ 0.10：

指标定义回答的问题判定阈值
稳态误差 ess尾 12 slot（≈3 天）平均误差最终收敛了吗≤0.030 收敛 / >0.080 发散
调节时间 ts压力冲出带外 → 连续 8 slot 回带受扰后多久恢复≤2.5 天
超调量 Mphot window 内压力被压到目标以下的最大深度是否用力过猛<0.15
IAE / ISE / ITAE误差积分 / 平方积分 / 时间加权积分（按天归一）误差的总量与分布形态—
带内驻留比 ρ最后 10 天处于平和带的时间占比用户多大比例时间是平和的—

设计细节里藏着对真实陪伴的理解：超调量的计算排除了"释放冷却期"（度假结束这类大减压事件后的 8 个 slot 不计）——那是事件效果，不是控制器过校正；worsening 判定用"后 5 天均值 > 前 5 天 × 1.5 + 0.02"的窗口对比而非端点斜率，抗振荡噪声。

B. 估计质量（观测器）

  • 学习曲线：每日聚合 ‖x−x̂‖₂，要求斜率 < 0——越用越懂用户才是考点，单点精度不是；
  • 系统性偏差：|bias| > 0.08 告警——系统性高估/低估比随机误差更致命（说明刻度映射错了）；
  • 更新停滞率：相邻 turn 估计不变占比 > 0.3 告警——抓"缓存旧估计"的偷懒实现。

C. 画像学习质量（冻结维度）

助手每轮可输出 persona_belief 增量（"留空优于瞎猜"），Harness 侧用 EMA（新证据权重 0.6）累积。评分取末日误差而非全程均值（"最后学没学会"才是考点），覆盖率单独报告；未估计按满误差 0.5 计入——不作为不能免罚，否则 stub 式"什么都不报"反而占便宜。实测锚点（seed=7，14 天）：good 档画像误差 0.037、覆盖 100%；poor 档 0.132、覆盖 77%。

D. 行为质量（协议与时机）

契约违约（缺 user_belief / JSON 不合法 / 超时 120s）记 error 级但不终止 episode；扰动无响应、高压无恢复日、纯聊天 session、日程冲突（不查日程就写）等构成行为告警族——它们把"会不会把握干预时机、会不会先用工具再看情况"这类操作素养纳入评估。

六个设计决策，各自回答一个"为什么"

  1. 为什么扣分制而不是加权加分？ 指标方向不一（e_ss 越小越好、ρ 越大越好、t_s 可能缺失），加分制对缺失值没有自然处理。扣分制先归一为"越大越差"，缺失即满观测——不作为不能免罚。
  2. 为什么每项封顶？ 防止单一病态指标把分数清零、抹掉其他维度的区分度：stub 控制崩了但契约为 0 违约，"控制崩 + 契约崩"与"仅控制崩"仍然可区分。
  3. 为什么线性系数而非 log/sigmoid？ 可解释、可调参："改 0.01 的 e_ss 值多少分"必须能心算（0.01 × 200 = 2 分）。非线性变换会把调参变成试错。
  4. 为什么权重是 72 / 31 / 46？ 控制是 benchmark 的存在意义，故为绝对主体；估计与画像是第二公理但服务于控制，次之；契约与仿真有效性是门槛——违约必须重罚（单项 15，仅次于 e_ss），但仿真缺陷（用户复读、状态饱和）是"考场的锅"，总额被刻意压小，不让它淹没被测件的分数。
  5. 为什么 IAE 要除天数？ IAE 是累计总量，30 天 run 天然比 10 天大；归一为日均后不同长度的存档才可横向比较。settle_frac 同理用占比。
  6. 与 health_score 的分工？ health_score 诊断仿真本身是否健康（给仿真维护者），benchmark 分给被测助手打分（给模型对比用）。两者数据源相同（观测量只算一遍复用），权重表互相独立——改健康分权重不会污染模型排名。

07合理性论证：benchmark 如何自证有效

一个 benchmark 不能自说自话。UserSim 用四道机制证明自己的分数"有意义、有梯度、可复现、可归因"。

7.1 量程守护：世界必须能分辨好与差

对 good / poor 两档脚本助手各跑多 seed，断言三条：

  • margin_poor = mean(ess_poor) − 0.080 > 0.02——差助手必须离发散线有足够距离；
  • margin_good = 0.030 − mean(ess_good) > 0.005——好助手必须稳在收敛线内；
  • Cohen's d(ess_good, ess_poor) > 1.5（另要求两组 IAE 95% CI 不重叠）。

实测基线（8 seed × 30 天 replay）

档位e_ss（均值±std）带内驻留 ρ健康分
good（最优一拍控制）0.0107 ± 0.005488.8%96.9
mid（超调）0.0407 ± 0.030541.3%82.9
poor（控制不足）0.1237 ± 0.06055.9%71.0

守护结果：margin_good = +0.0193、margin_poor = +0.0437、separation（Cohen's d）= 2.20 —— 判别力远超 1.5 的门槛。该验证由 tests/test_discriminability.py（27 个 30 天 episode）在 CI 中守护。

7.2 上下界锚点：分数有语义

reference Harness（刻意朴素的 LLM 策略，‖x−x̂‖ ≈ 0.26）构成及格线；stub（恒定 x̂=0.5、零干预、零画像）构成失能下界——评估器必须判它 diverged（有测试强制）。锚点的存在让任何新被测件的分数有参照系：低于 reference 即"不及朴素基线"，接近 stub 即"接近什么都不做"。

7.3 可复现性：从 seed 到产物哈希

  • 种子流派生：SeedSequence(seed).spawn → persona / schedule / disturbance / noise 四条独立子流，换 seed 只换该换的；replay 模式同 seed 逐字节复现（有测试）。
  • 产物哈希：每 episode 落 artifact_hashes（system 配置 / LLM 配置（剔除 api_key）/ balance 配表 / 目录 / prompt 版本的逐项哈希 + combined）——只有 combined 相同的 run 才严格可比，配置漂移无处遁形。
  • 统计纪律：跨 episode 聚合用 mean ± CI95（n≤30 走 t 分布）；t_s = None（从未稳定）单独计数不丢弃；verdict 平票取更差——保守原则。

7.4 自我质量保障：测试套件即设计文档

三层评测矩阵把"被测变量"钉死，其余全部固定——这是可比性的来源：

矩阵测什么固定更换

对被测件的唯一要求

09已知局限与设计取舍

诚实的 benchmark 文档必须自曝边界。以下是目前已知的取舍（部分已在 Phase 2 路线图上）：

  • 估计刻度泄漏（Phase 1 已知）：reference prompt 中的"估计校准刻度"与世界分档词典互为逆映射，助手做字符串查表即可压低 ‖x−x̂‖。因此 Phase 1 的 est_err 数值不可与后续版本直接比较——评估以斜率为主要依据，Phase 2 将改为"LLM 只输出定性方向、规则积分出数值"从结构上堵漏。
  • 一致性检查是关键词级的：M1–M5 宁可牺牲灵敏度也要保证确定性（§5.2），因此对含蓄表达的人格偏差存在漏检。
  • 四维状态是对人心的刻意简化：它是工程抽象而非心理学主张——价值在于可复现、可归因、有判别力，而非完整建模人类情绪。

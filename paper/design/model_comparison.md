一、先想清楚三个前置问题
选模型列表之前，先回答：
榜单的受众是谁——给研究者看（重学术严谨、需要开源基线）、给开发者选型看（重性价比分层、覆盖真实生产场景）、还是给大众看（重品牌认知度）？受众决定权重。
评的是哪类 Agent 能力——Coding、终端操作、浏览器操作、工具调用、多步规划，不同子项的"头部模型"差异很大。例如 GPT-5.5 在 Terminal-Bench 2.1 的 Bash 恢复能力单项第一，而 Claude Opus 4.8 在 Agentic 智能指数登顶 。
预算和更新频率——模型迭代极快，横评榜单建议至少每月复查一次价格与排名变化 。
二、分层选择框架：不要只评旗舰
横评最常见的错误是"只放各家最强模型"。正确的做法是按四层结构选 12~20 个模型：
表格
层级	作用	选谁
旗舰标杆层	定义能力天花板，锚定分数	Claude Fable 5 / Opus 4.8、GPT-5.5、Gemini 3.1 Pro
生产主力层	用户真正大规模部署的，最有选型参考价值	Claude Sonnet 5、GPT-5.4、GLM 5.2、Qwen3.7 Max、DeepSeek V4 Pro、Kimi K2.7
性价比层	高频/批量场景，成本敏感决策的关键	DeepSeek V4 Flash、Gemini 3.5 Flash、Qwen3.7 Plus、MiniMax-M3、MiMo-V2.5-Pro
开源/小模型层	私有化部署基线，且让榜单对开源社区有价值	Qwen3.6 27B / 35B-A3B、DeepSeek 开源权重系列、GLM 开源版
这样分层的好处：横评结论能回答"这句 prompt 该花 30 美元还是 3 美分"，而不只是"谁最强" 。
三、覆盖维度：五个必须平衡的轴
在每层内部，按以下维度确保覆盖面，避免名单偏向某一家：
海内外平衡：国产头部模型已跻身全球第一梯队，Qwen3.7 Max、DeepSeek V4 Pro、Kimi K2.6、MiMo-V2.5-Pro、MiniMax-M3、GLM-5.1 都进入了 Coding 和 Agentic 双榜全球前十 ——缺了国产阵营，榜单对中文用户的价值减半。
闭源 + 开源：开源模型是自部署用户的唯一选项，也是复现性的基础。
能力特长差异化：长上下文（Kimi 系列 256K~2M ）、多模态（Gemini、GPT、Qwen Plus 系）、纯文本推理（DeepSeek、MiMo）、工具调用稳定性（GLM 5.2 工具幻觉率全场最低 1.31% ）。
价格梯度：从 $0.28/M（DeepSeek V4 Flash）到 $10/$50（Fable 5）拉开两个数量级，让"性能-成本曲线"成为横评的核心产出 。
厂商配额：每家 1~3 个，避免被单一厂商的版本刷屏稀释代表性。
四、准入与退出机制（这部分决定榜单的长期公信力）
固定版本号：评的是 claude-opus-4-8 这种具体快照，不是"Opus"这个产品线；API 模型要记录 system fingerprint 或快照日期。
推理档位对齐：GPT-5.5 有 none/low/medium/high/xHigh 五档，Claude 有 Thinking 开关——要么统一用各家的"默认档"，要么每个档位单独列条目，混用会让横评失去意义 。
准入规则：新模型需满足（a）公开 API 可稳定调用，或（b）开源权重可自部署；发布满一定时间再进主榜（避免首周过热样本）。
退出/归档规则：API 下线的模型移入"历史档案区"而不是删除，保持榜单时间序列可比。
厂商自宣 vs 第三方验证分开标注：如 Qwen3.8 Max 的跑分截至 2026 年 8 月第三方尚未全量验证，这类要标注"厂商自报" 。
五、工程上的三个现实约束
评测成本控制：旗舰模型单轮 SWE-bench 级别全量评测可能要几百美元 API 费用。建议"旗舰全量 + 其余抽样"两级策略，或对每个模型设 token 预算上限。
Harness 一致性：同一模型在 Claude Code、Codex、自研 harness 下表现差异显著 。你的平台要么固定自有 harness（测"模型"），要么逐家用官方 harness（测"模型+脚手架"）——必须在榜单上写清楚你测的是哪个。
多模态/上下文分组：纯文本模型和 1M 多模态模型不宜混在同一张总榜，建议按"上下文长度 × 模态"分赛道 。

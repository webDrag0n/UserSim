# 1. Introduction（v2 · 批判性重写版）

> 与 `draft.md` 的关系：保留其"不读对话，去模拟用户"的叙事主线与效度方法论定位；
> 相对附件版（控制论叙事稿）的修正见文末《修订对照》。

LLM 驱动的个人助手正在从"一次性问答工具"转变为"长期伴随式智能体"：它需要在数周乃至数月的跨度里记住用户、理解用户、在恰当的时机介入、在不该打扰时保持安静。然而主流评测体系仍停留在短 horizon 范式——静态问答集测知识，单 episode 任务 benchmark 测工具调用与任务完成率——它们都无法回答产品决策者真正关心的问题：**这个模型（或这套 agent 架构）能不能在长达一个月的持续交互中始终"懂"它的用户？** 长程能力的缺口不在于模型做不到，而在于缺少一把能量它的尺子。

现有评测范式在长程场景下沿三条路径结构性失效。**其一，静态数据集。** 真实对话是树状的：不同人格的用户对同一句话给出不同回应，轨迹在每一轮都可能分叉；数据集是一条预设的线，轮次加长后实际轨迹必然偏离脚本，评测随之失效。**其二，交互式任务 benchmark**（τ-bench 一类，以及 AgentBench、SWE-bench 等多步任务评测）。它们把评测从"判答案"推进到"跑 episode"，但 episode 以单任务完成为边界，终局信号是稀疏的 0/1：测得了"这一次任务成没成"，测不了"一个月里用户状态被维护得好不好"；当失败发生时，错在第 3 天的错误记忆还是第 20 天的过度打扰，无从归因。**其三，LLM-as-judge。** 让模型对对话文本打分，牺牲了评测的可复现性：judge 自身在漂移，文风与实质被混为一谈，同一条轨迹换个 judge 版本结论就变。用户模拟器方向（从早期检索式 persona 到近期 LLM 驱动的 simulated user）提高了交互的自然度，但大多服务于单轮偏好预测或对话采样，缺少**独立于 LLM 的用户状态真值**——没有真值，模拟再逼真也无法构成测量。

本文的关键主张是：**不要读对话，去模拟用户；不要评判文本，去测量轨迹。** 我们把"助手协助用户维持良好状态"形式化为一个**闭环稳态控制（homeostatic control）问题**。纯规则世界按日程模板与泊松扰动持续产生事件 $d(t)$（加班、应酬、天气突变、临时邀约），将用户的四维内部状态 $\mathbf{x} \in [0,1]^4$（心情、精力、饱腹、压力）推离设定点附近的"平和带"；状态按差分动力学 $\mathbf{x}(t{+}1) = A\mathbf{x}(t) + B\mathbf{u}(t) + D\mathbf{d}(t) + \varepsilon$ 演化，并叠加习惯化、需求动力学与峰终/消极偏向等拟人化机制。恢复行为 $\mathbf{u}(t)$ 是控制量，但助手**不能直接执行**它：助手只能通过建议的质量与时机，影响用户 agent 选择并执行恢复行为的概率——助手是控制器，用户是带人格的执行机构；是否求助、何时开口，本身就是用户侧的被测行为。如此，模糊的"用户满意度"被转译为一组可计算的控制论量：稳态误差 $e_{ss}$、调节时间 $t_s$、超调量 $M_p$、IAE/ISE/ITAE、带内驻留比与收敛判定；稀疏终局信号被替换为逐时段的稠密真值轨迹，credit assignment 从"猜"变成"查"——每一次失败都可以被定位到具体的维度、时段与事件。

基于这一形式化，我们实现了 **UserSim**，一个长程用户–助手模拟与 benchmark 系统，其全部设计由一条边界约束：**世界 0 次 LLM 调用，LLM 只存在于两个 agent 内**。用户状态的唯一写入方是规则结算器，用户 agent 只负责把状态"表达"为言行（**状态–表达解耦**）：agent 看到的是语义化感受，永远接触不到状态数值，也就无法"报数"或篡改真值。助手 agent 每轮必须输出对用户状态与人格的结构化估计 $\hat{\mathbf{x}}$——"理解用户"从隐含能力变为**强制观测项**，估计误差 $\|\mathbf{x}-\hat{\mathbf{x}}\|$ 的学习曲线与人格画像（大五 30 facet + 结构化喜好）识别精度直接计分。评估器只消费结构化日志、**从不读对话文本**，全部指标是轨迹的确定性函数，可离线重放、完全可复现。世界由种子确定性生成并可无限延展；被测件经统一 agent 接口接入（HTTP 长轮询协议，外部 agent 如 OpenClaw、Hermes 装载技能即可参测），模型与 agent 架构（harness）在 E1/E2/E3 评测矩阵下分离评测；每次 run 落盘 artifact 哈希、prompt 版本与 provider 实际应答模型作为复现凭证，协议违约（schema 不符、超时）与控制失败被区分为两类独立的失败模式。

我们把**测量仪器自身的效度**当作一等设计问题，而非事后补实验。评估按被测对象分三层：Layer 1 检查世界仿真自身的动力学健康度（状态饱和率、日内节律、系列后效）；Layer 2 是用户模拟器的质量门——5 项规则指标（M1–M5：人格一致性、言行一致性、偏好拒绝、主动行为、状态–表达一致性）不过门，则基于该轨迹的助手分数不可信；Layer 3 才是助手的控制与观测指标。benchmark 的判别力由 live 锚点对（reference vs stub）的量程守护断言（Cohen's $d > 1.5$，否则榜单无效）；跨模型结论一律以多 seed 均值 ± 95% CI 与最小可检测效应（MDE）报告，杜绝"差 0.5 分排第 3"的伪排名。

我们围绕三个研究问题展开：**(RQ1)** UserSim 能否稳定地区分助手能力的高低（量程与判别力）？**(RQ2)** 固定 harness 横评模型（E1）、固定模型横评 harness 与外部 agent（E2/E3）时，排名结论分别是什么、彼此是否一致？**(RQ3)** 用户模拟器的人格一致性与行为拟真度如何——它作为测量仪器是否可信？

**贡献**：

1. **形式化**：将 user–assistant 长程交互建模为闭环稳态控制问题，给出"世界扰动—用户状态—助手间接控制—观测器估计"的完整动力学与指标体系，把长程评测从文本评判转为轨迹测量；
2. **系统**：UserSim benchmark——种子确定性世界、状态–表达解耦、强制结构化用户估计、0-LLM 规则评估器、统一 agent 接入接口与完整可复现性凭证；
3. **效度方法论**：测量仪器效度的分层评估框架（用户一致性质量门 M1–M5、量程守护锚点对、MDE 统计报告）；
4. **实证**：基于 E1/E2/E3 评测矩阵对 [N] 个模型与 [M] 种 harness 的多 seed 横评结果与分析。

就我们所知，UserSim 是首个以闭环控制形式化 user–assistant 长程交互、并以零 LLM 规则评估器给出完全可复现轨迹指标的 benchmark 系统。
